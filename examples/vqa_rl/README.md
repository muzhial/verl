VQA：基于 RL 的鲁棒性 VQA 项目实践

## 1. 项目概述

### 1.1 项目目标与多模态思维链VQA任务定义

本项目，命名为 VQA，旨在利用先进的强化学习（RL）技术，训练一个高性能且具备卓越鲁棒性的视觉问答（VQA）系统。核心目标是显著提升模型在处理复杂多模态科学问答任务中的性能，不仅追求最终答案的准确性，更强调生成推理过程的逻辑自洽性（Self-Consistency）与可验证性（Verifiability）。

该 VQA 任务要求模型必须综合分析输入的图像信息和配套的多项选择题，并遵循严格的结构化输出规范。模型被要求首先生成一个详尽的、逐步的推理过程，即思维链（Chain-of-Thought, CoT），随后提供最终的单字母选项答案。这种结构化输出是项目后续实施复合奖励机制，特别是逻辑校验奖励 ($R_{Consistency}$) 的基础。

输出结构必须严格遵守以下格式，任何不符合该结构的输出都将受到惩罚：

```text
<think>

</think>
<answer>

</answer>
```

### 1.2 现状与挑战：多模态推理的可靠性与可解释性

当前的视觉语言模型（VLM）在面对如 ScienceQA 这种需要多步推理和跨模态信息整合的科学问答任务时，仍然面临显著挑战。这些挑战主要源于现有训练方法难以有效评估和优化模型内部的推理质量。

首先，主要的瓶颈在于推理过程的因果不完整性。许多模型生成的 CoT 往往是对于最终正确答案的“事后合理化”或表面描述，而不是真正驱动答案产生的充分逻辑步骤。如果一个 CoT 无法独立于原始视觉上下文来验证其逻辑链，那么该模型的推理过程就是不可信赖的，其鲁棒性和可信度将大打折扣。这意味着模型可能在偶然猜对的情况下，生成一个看似合理的 CoT，而传统方法无法有效地检测这种“伪推理”现象。

其次，传统奖励信号的稀疏性与不匹配严重限制了模型对高质量推理的优化。传统的强化学习方法通常仅依赖最终答案的二元准确性奖励 ($R_{Acc}$ 为 1 或 0)。这种稀疏的信号无法解耦复杂的优化目标，例如同时满足内容准确、逻辑清晰和格式正确的要求。特别是对于推理过程的质量，单一的二元奖励无法提供细粒度的指导，导致强化学习过程中的奖励空间稀疏，难以有效引导策略模型优化其内部推理机制。因此，本项目必须设计一套能够对逻辑结构和推理质量提供密集、精细化反馈的复合奖励机制。

### 1.3 项目技术路线与创新点

为克服 VQA 任务中对鲁棒性和可解释性的挑战，本项目采取了基于强化学习的优化技术，并以 Qwen2.5-VL-7B-Instruct 模型作为基础策略模型。技术路线的核心在于构建一个能够提供密集且高质量反馈的复合奖励机制，以指导模型学习生成具备自洽性的结构化思维链。

项目的策略模型通过 RL 优化，目标是最大化复合奖励函数：

$R_{Total} = 0.7 \times R_{Acc} + 0.3 \times R_{Consistency} + R_{Length} + R_{Format}$

本项目在奖励机制方面实现了两大核心创新：

1. 一致性奖励 ($R_{Consistency}$): 引入创新的两阶段逻辑校验框架。该机制通过要求模型在没有图像输入的情况下，仅依据自身生成的 CoT 来重新推导答案，从而对 CoT 的内在逻辑自洽性和独立有效性进行量化评估。这种方法显著提升了 VQA 结果的可解释性和可靠性。
2. 条件长度激励 ($R_{Length}$): 设计了一种智能化的长度惩罚/激励机制。该机制仅在模型未能给出正确答案时 ($R_{Acc}=0$) 才会激励其进行更长、更深入的思考（即生成更长的 CoT），而在回答正确时则强制豁免长度惩罚 ($R_{Length}=0$)，以实现深度推理与生成效率之间的动态平衡。

## 2. 强化学习优化奖励机制设计

本项目采用分层复合奖励设计，旨在精确解耦 VQA 任务中的多个优化维度，包括准确性、逻辑鲁棒性、深度探索和格式遵循。

### 2.1 总奖励函数架构与分层逻辑

模型的总奖励 $R_{Total}$ 由四个加权分量组成：

$R_{\text{Total}} = 0.7 \times R_{\text{Acc}} + 0.3 \times R_{\text{Consistency}} + R_{\text{Length}} + R_{\text{Format}}$

其中，$R_{Acc}$ 是主导项，$R_{Consistency}$ 扮演了关键的逻辑正则化角色。尽管 $R_{Consistency}$ 的权重系数为 0.3，但其设计逻辑确保了对策略模型生成高质量 CoT 的强大引导力，尤其是在高准确率样本中，它能够区分出高质量的推理与不可信的“伪推理”。

### 2.2 Acc Reward: 基础准确性量化

准确性奖励 ($R_{Acc}$) 是 VQA 任务的基础，它直接反映了模型最终选择的正确性。如果模型给出的选项与标准答案一致，则 $R_{Acc}=1.0$；否则，$R_{Acc}=0.0$。

### 2.3 Consistency Reward：核心逻辑与鲁棒性验证机制

$R_{Consistency}$ 旨在通过量化思维链的逻辑自洽性，来确保模型的推理过程是可靠且可追溯的。

#### 2.3.1 机制设计：两阶段逻辑校验

该机制的关键在于对模型生成的 CoT 进行“外部审计”：

1. 阶段一（初始生成）: 模型基于完整的输入（图像、问题和选项）生成 CoT ($C_1$) 和答案 ($A_1$)。
2. 阶段二（逻辑校验）: 系统将 $C_1$ 和选项（顺序被打乱）作为输入，并要求模型严格扮演“逻辑校验器”的角色，仅依据 $C_1$ 中提供的信息推导出答案 ($A_2$)。该过程排除了所有视觉输入，只验证 $C_1$ 是否包含了足够支持结论的逻辑证据。

这种设计保证了生成的 CoT 必须具有因果完整性。如果 $A_1$ 的正确性依赖于图像 $I$，则 $C_1$ 必须显式地将 $I$ 中的关键视觉观察结果转化为文本形式的证据。如果 $C_1$ 遗漏了关键的视觉证据，那么在阶段二缺乏图像上下文时，$A_2$ 将无法得出正确的结论，从而导致低 $R_{Consistency}$ 惩罚。

#### 2.3.2 评分逻辑：四种状态下的奖励值设定

$R_{Consistency}$ 的评分逻辑旨在精细地指导模型修复其 CoT 缺陷：

| 情景 | A1（基于多模态输入） | A2（仅基于 CoT） | CoT 逻辑状态 | $R_{Consistency}$ 值 |
| --- | --- | --- | --- | --- |
| I. 理想 CoT | 正确 (1) | 正确 | 逻辑自证完整 | 1 |
| II. 正确但 CoT 缺陷 | 正确 (1) | 错误 | 逻辑不自洽 | 0.5 |
| III. 错误但意外自洽 | 错误 (0) | 正确 | 逻辑不自洽 | 0.5 |
| IV. 逻辑稳定但错误 | 错误 (0) | 错误，且 $A_1 = A_2$ | 逻辑一致 | 0.1 |
| V. 逻辑混乱且错误 | 错误 (0) | 错误，且 $A_1 \ne A_2$ | 逻辑混乱 | 0 |

### 2.4 Length Penalty Reward：深度思考的激励与边界控制

$R_{Length}$ 用于策略性地调节 CoT 的长度，目的是鼓励深度思考，同时防止生成冗余或过长的文本。

#### 2.4.1 惩罚函数定义与参数

惩罚函数 $R_{Length}$ 旨在将 CoT 长度 $L$ 引导到 $l_{opt}$ (100) 到 $l_{max}$ (200) 的优化区间。关键参数设定为：$l_{min} = 50$，$l_{opt} = 100$，$l_{max} = 200$

$R_{\text{Length}}(L) = \begin{cases} -1 & \text{if } L < 50 \\ -1 + \frac{L - 50}{100 - 50} & \text{if } 50 \le L < 100 \\ 0 & \text{if } 100 \le L \le 200 \\ -1 & \text{if } L > 200 \end{cases}$

#### 2.4.2 豁免机制

$R_{Length}$ 的设计体现了一种条件激励策略：如果 $R_{Acc}=1.0$（即模型已答对），则 $R_{Length}$ 强制设定为 0。

这种机制确保了效率与探索的解耦。当模型已经高效地找到了正确答案时，任何额外的 CoT 长度都是冗余的；因此，将 $R_{Length}$ 归零，旨在奖励简洁高效的正确推理。反之，只有当模型回答错误时，惩罚函数才被激活，此时模型被激励生成 $100 \le L \le 200$ 的长 CoT，以促进对复杂或未解决问题的深度探索，从而优化策略在困难样本上的表现。

### 2.5 Format Reward: 结构化输出的硬约束

格式奖励 ($R_{Format}$) 作为一个硬性约束，确保模型的输出严格符合 1.1 节定义的 &lt;think&gt;...&lt;/think&gt; 和 &lt;answer&gt;...&lt;/answer&gt; JSON 结构。如果输出满足格式规范，则 $R_{Format}=0.0$；否则，$R_{Format}=-1.0$。这是保证后续奖励计算和逻辑校验流程能够有效运行的前提。

## 3. 数据集构建与预处理流程

### 3.1 核心数据集概况

本项目基于 derek-thomas/ScienceQA 数据集进行 VQA 系统的训练和评估。该数据集中包含约 1.2 万个多模态科学题目，以其对复杂逻辑推理能力的高要求而闻名。

ScienceQA 的每条数据项都包含丰富的上下文信息，例如图像、问题、选项和标准答案。核心字段包括图像的字节流对象 (image)、问题 (question)、选项 (choices) 和答案 (answer)。此外，数据集还提供了如 lecture（教学文本）和 solution（标准解法步骤）等辅助字段，这些信息为 RL 训练提供了丰富的数据基础。

### 3.2 数据筛选与最终数据集划分

原始的 ScienceQA 训练集规模约为 12.7K 条数据。为了确保 RL 训练的高效性及鲁棒性，项目执行了严格的筛选流程，旨在排除不适用的或残缺的样本：

1. 图像有效性过滤: 剔除 image 字段为空的数据。由于这是一个 VQA 项目，缺乏图像输入的多模态样本必须被排除。
2. 选项数量过滤: 仅保留选项数量大于等于 2 的数据，确保 VQA 任务的有效性。

经过上述筛选，原始训练集规模缩减，但数据质量得到显著提升。

| 数据集类型 | 原始样本量 | 最终筛选样本量 |
| --- | --- | --- |
| 训练集 | 12.7K | 6,218 条 |
| 测试集 | 4.24K | 2,017 条 |

最终，训练集和测试集分别为 6,218 条和 2,017 条样本。

## 6. 详细过程分析

- **奖励计算**：自定义 reward manager (rewards.py) 对每条样本并发执行 `process_reward`：
  - **格式惩罚**：`get_format_reward` 用正则确保输出恰好含一个 `<think>` 和 `<answer>`，否则 -1。
  - **准确率奖励**：直接比较 `response` 与 `ground_truth` 得到 1/0。
  - **一致性奖励**：`make_prompt` 将首次生成的 CoT 与重新打乱的选项重组为验证 prompt，通过 `request_verifier` 发送给外部逻辑检查模型；依据初答/复核答的正确性与一致性，按文档中五种情景给出 1、0.5、0.1 或 0 分，实现 “CoT 脱离图像仍能自洽” 的约束。
  - **长度奖励**：`get_length_penalty` 用 tokenizer 统计 CoT 长度，在回答错误时把长度压到 50–200 token 区间（短/过长均 -1，落在 [50,100) 线性上升，100–200 得 0）；若答对则该项强制 0，实现“出错才鼓励深思”。
  - 所有奖励按 `R_total = 0.7*Acc + 0.3*Consistency + Length + Format` 汇总后回传给 PPO 算法。

- **训练循环**：GRPO 结合 PPO-style advantage（`actor_rollout_ref.actor.ppo_*` 参数）更新策略，KL 项保持与参考模型接近；`trainer.save_freq/test_freq=10` 控制 checkpoint 与快速评估，`trainer.val_before_train=True` 先跑一次验证集基线。SwanLab/console logger 记录指标，输出模型保存在 `OUTPUT_PATH`。

- **模型评测**：完成训练后，`eval/run.sh` 通过 vLLM 部署推理服务（`vllm serve VQA-RL-ckpt-stepXXX`），再执行 `get_model_response.py` 和 `print_metric.py`：前者遍历 `scienceqa_test_data.jsonl` 请求模型、保存 `<think>/<answer>`；后者比对 `ground_truth` 计算 Acc。官方对比显示从 80.91%（原模型）提升到 91.03%。

- **关键注意事项**：确保 Hydra override 与当前配置匹配（如 `actor_rollout_ref.rollout.update_weights_bucket_megabytes` 需要在 config 中存在或用 `+` 追加），CUDA 驱动/显卡可见 (`nvidia-smi` 正常) 后再运行脚本，且在 reward 阶段自建 verifier 要和 `SELF_VERIFIER_SERVER_NAME` 一致。
